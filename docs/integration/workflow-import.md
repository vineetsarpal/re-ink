# Reference workflow import and provider overrides

The inactive export is [`workflows/n8n/reink-extraction-v1.json`](../../workflows/n8n/reink-extraction-v1.json). It contains runnable core HTTP/Code/IF/Wait nodes, without credential IDs/names, secret headers, pinned executions, or customer URLs. The stable production path is `/webhook/reink-extraction-v1`. This artifact targets **n8n 2.43.4**; Webhook 2.2, Respond to Webhook 1.5, HTTP Request 4.5, Wait 1.1, Code 2 and IF 2.3 are pinned. Import/runtime compatibility has **not** been exercised: n8n and its Docker daemon were unavailable. Source/fixture checks are separate from the live gates below. See the [release manifest](../../workflows/n8n/release-manifest.json).

## Build and deterministic checks

Run from the repository root, with the backend environment installed:

```sh
backend/.venv/bin/python workflows/n8n/generate_schema.py
node workflows/n8n/generate_workflow.cjs
node --test workflows/n8n/tests/*.test.cjs
```

`generate_schema.py` imports `ContractFacts`, `PartyFacts` and currency/limit constants from the backend. The generated business schema requires all provider properties and makes optional values nullable, forbids extra properties, and bounds party count. It supplies both REST branches. The canonical backend remains authoritative, including semantic validation the provider JSON schema cannot encode. Never hand-edit the generated schema/export. The tests verify regeneration, compile the embedded Code sources, exercise binary/request preparation and retry decisions, and validate synthetic normalized PDF/DOCX/OpenAI outputs with the real backend `NormalizedExtractionResult`. Fixtures are documentation-derived synthetic inputs, **not captured provider responses**. Tests do not run n8n or external providers.

## Local binding and activation

1. Import the export **inactive** into the pinned n8n instance. Use the regular-mode/persistent binary-volume, encryption-key and pruning setup in [n8n reliability](n8n-reliability.md). Restrict editor access; never pin documents. Keep the export inactive until all checks pass.
2. Create a local **Header Auth** credential for the webhook. Bind it to `Extraction webhook`. Its header name/value must match the backend dispatcher's separately issued dispatch service credential. The export intentionally has no credential object or identifying placeholder name/ID.
3. Create a different local **Header Auth** credential for n8n-to-re-ink requests with the backend-issued scoped identity and expected service header (normally `Authorization: Bearer …`, as configured by the backend operator). Bind that same scoped credential to `Claim attempt`, `Fetch original` and `Deliver event`. It has document/claim/callback access for the configured organization and no approval privileges. Do not reuse the dispatch credential.
4. Create provider Header Auth credentials in n8n storage. Bind the LandingAI bearer key to `LandingAI Parse` and `LandingAI Extract`; bind the OpenAI project bearer key to `OpenAI Responses`. Do not put credentials in Code, Set/config nodes, workflow JSON, prompts, app environment variables, or the browser. Provider calls use fixed HTTPS origins, and all HTTP nodes disable redirect following and automatic retries. Add any required project/organization authorization through the credential mechanism locally; never commit headers.
5. Set non-secret overrides in [`config.json`](../../workflows/n8n/config.json), regenerate, and re-import inactive; alternatively edit only the `config` literal at the top of `Entry` and preserve a sanitized local override record. Set `backendOrigin` to the trusted HTTPS origin **without trailing slash or path/query/credentials**, `provider` to `landingai` or `openai`, and explicitly choose compatible provider model IDs and prompt. Default `.invalid` backend origin and `SET_COMPATIBLE_*` model placeholders intentionally prevent accepting unconfigured work (HTTP 503). All provider model IDs are intentionally unset. Configure documented available exact ADE versions: the adapter rejects fallback or resolved-version mismatch. Do not use moving aliases unless the version policy and adapter are deliberately updated and tested. For OpenAI, select a file/Structured Outputs/PDF vision compatible model actually accessible to the project and test DOCX support. Record requested and resolved models in a deployment copy of the release manifest.
6. Run authenticated fixture/lifecycle tests and both live branches with synthetic inputs. Publish/activate only after the gates below pass. Point the dispatcher at the production stable webhook with the matching dispatch credential. Use a coordinated operator procedure to rotate each credential at both authenticated ends.

`Entry` freezes the non-secret branch/model/prompt/backend-origin/schema configuration for each execution. Downstream nodes read that captured item rather than live configuration. Switch providers only between jobs and do not rerun provider nodes or resume a different execution to bypass claim ownership. The app has no provider selector or provider API keys. HTTP Request replaces its input; Code nodes explicitly restore Entry/claim context and original binary, and create a new markdown binary before ADE extraction. The OpenAI request reads actual bytes with n8n's binary helper, supporting filesystem binary storage rather than assuming binary `data` is base64.

## Behavior and limits

Malformed dispatch gets 422 before claiming; valid configured dispatch gets the exact identity-matching 202 acceptance. A claim runs before document/provider access. Only a matching HTTP 200 `run` with a future backend deadline proceeds. `already_claimed`, expired/malformed or rejected claim responses stop without submitting a failure for another owner. Lost claim responses may leave an owned but unfinished attempt; the backend timeout makes that visible and a human can start a new application attempt. Provider POSTs are never automatically retried after transport ambiguity.

Original retrieval permits PDF/DOCX MIME types, up to the application 50 MiB ceiling. OpenAI additionally rejects files **at or above 50,000,000 bytes** before the provider call. ADE's synchronous API enforces its own 100-page ceiling; successful responses declaring more than 100 pages, partial HTTP 206, failed pages, warnings, schema violations and model fallback are safe failures. A local preflight page count is not claimed. Provider request/context/proxy limits can still reject a smaller file. No implicit asynchronous-API switch or cross-provider fallback exists.

ADE Parse Markdown reaches Extract unchanged with its IDs, as a multipart file; the generated schema is a JSON string and `strict=true`. The normalizer traverses nested extraction metadata, resolves each first usable reference in global grounding, obtains actual chunk/HTML element text, normalizes markup/whitespace without joining distinct text nodes, and converts zero-based PDF pages to one-based review pages. It omits unresolved evidence, figure descriptions and confidence. Invalid PDF boxes and dangling/misaligned evidence fail. DOCX retains quotations and omits converted-page coordinates. These are structural checks; real quotation/location correctness requires live source review. One representative source per field is retained, preserving party order.

OpenAI sends a PDF/DOCX data URI to Responses with `store:false`, the configured prompt and strict generated schema. It inspects completed/refusal/incomplete/output states, rejects invalid/no-useful facts, and omits all evidence/confidence. This does not establish provider retention policy or extraction accuracy. Humans must verify results against the original. Raw provider errors are never sent to re-ink; safe bounded static failure messages replace them. Oversize callbacks become explicit `OUTPUT_LIMIT` failures rather than truncated successes.

`Freeze event` constructs one stable terminal event/ID per execution. Callback delivery preserves that event unchanged; 429, 5xx, transport errors and invalid successful acknowledgements use an explicit Wait loop with jittered 5–60 second backoff and bounded numeric/date Retry-After. Every delivery and provider timeout is bounded by the returned backend `deadline_at`. Authentication/schema/conflict/stale/deleted rejections stop delivery. **A lost completion acknowledgement never becomes a failed event**. No direct app database access or provider retry loop exists. Sub-65-second waits are in-process, not a durable callback outbox; a process crash can lose delivery until backend timeout/manual retry. See [reliability boundaries](n8n-reliability.md).

## Required live evidence and upgrades

Before declaring this workflow deployable, import on the target n8n version and verify all locally bound credentials and multipart/binary handling. Exercise malformed dispatch, competing authenticated deliveries, loss around acceptance, owner crash, claim fencing, callback replay/conflict, 429/5xx/network/invalid-ack backoff/Retry-After/deadline, early completion, deletion/stale attempts, restart persistence and cleanup. Confirm execution data/binary pruning and manual reset on the real instance.

Then run the **same labeled synthetic corpus** through LandingAI and OpenAI on the same re-ink build, changing only trusted n8n configuration. Include PDF, DOCX, ambiguous/missing facts and unreadable inputs; capture sanitized live response shapes and actual requested/resolved model/API versions. Measure field correctness and ADE quotation/location correctness separately and disclose OpenAI's evidence gap. Neither branch has been called in this implementation; the two-live-provider acceptance gate remains open. Synthetic fixtures do not replace it. See [provider evidence](evidence.md#provider-response-reference) and the project evaluation gate.

For an upgrade, retain the previous sanitized export and non-secret overrides, regenerate against the new backend schema, compare node/schema/lifecycle versions, reapply overrides, bind local credentials and rerun fixtures plus both live smoke tests inactive. Activate between jobs. Roll back to the preserved compatible workflow/config version explicitly; never change behavior midway through an owned attempt. Do not export customer execution data, actual original files, provider responses, identifying credential names/IDs or secrets into the repository. Seven-day n8n pruning does not control provider-side copies.
